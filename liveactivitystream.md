# Live Activity Streams

This is the canonical index for the two source-labeled live activity streams
for the `qmoi-enhanced` repository. The streams are generated by
`scripts/live_activity_stream.py` and uploaded by GitHub Actions whenever the
autonomous-agent workflows change, on their schedules, and through manual
dispatch.

## GitHub UI

- [Combined QMOI and Ollama stream workflow](https://github.com/thealphakenya/qmoi-enhanced/actions/workflows/ollama-live-activity-stream.yml)
- [QMOI stream workflow](https://github.com/thealphakenya/qmoi-enhanced/actions/workflows/qmoi-live-activity-stream.yml)
- [Ollama autonomous-agent workflow](https://github.com/thealphakenya/qmoi-enhanced/actions/workflows/ollama-autonomous-agent.yml)
- [All workflow runs](https://github.com/thealphakenya/qmoi-enhanced/actions)
- [Scheduled stream runs](https://github.com/thealphakenya/qmoi-enhanced/actions?query=branch%3Amain+event%3Aschedule)

Open the newest run, select **Summary**, and download the artifact named
`qmoi-live-activity-stream` or `ollama-live-activity-stream`. The artifact
contains JSON and text tracker files, including the exact event timestamp,
source, status, message, and remote run URL where available.

## Stream outputs

The repository-visible files are updated by the generator and are useful for
local inspection or downstream automation:

- `ollamatracks/live_activity_stream.json`: combined QMOI and Ollama events.
- `ollamatracks/qmoi_live_activity.json`: QMOI-only events.
- `ollamatracks/ollama_autonomous_agent_live_activity.json`: Ollama-only events.
- `ollamatracks/LATEST_ACTIVITY.txt`, `CURRENT_STATUS.txt`, and `STATE.txt`:
  compact latest-state views.

Each JSON event has `source`, `entity`, `event`, `status`, `message`,
`timestamp_utc`, and `details`. QMOI events expose repository/runtime health;
Ollama events expose active GitHub workflow runs when authenticated and fall
back to a clearly labeled local tracker heartbeat when remote run data is not
available. A fallback is never presented as live remote inference.

## Automatic runtime behavior

The two workflows listen for autonomous-agent workflow lifecycle events and
also run on schedules, so the streams continue updating when either runtime is
active. `workflow_dispatch` is available for an immediate refresh. The
generator reads GitHub Actions run status using the workflow token and reads
the local tracker state for degraded or unauthenticated environments.

Use the workflow run page for live job logs and the uploaded artifact for a
timestamped snapshot. GitHub Actions artifacts are snapshots rather than a
websocket; the scheduled runs are the supported live-refresh mechanism.

## Verification contract

An operationally live stream must contain both `qmoi` and
`ollama_autonomous_agent` source labels, a fresh `timestamp_utc`, and either a
remote workflow URL or an explicit `local_tracker` fallback. Failed runs,
stale tracker files, invalid authentication, and dirty or behind repository
state remain visible as warning/failure statuses instead of being hidden.
