# QMOIMODEL.md - QMOI Model and Evaluation Contract

## Canonical Runtime

QMOI is the primary orchestration/runtime layer. Ollama is a compatibility provider and fallback until the evolution transition gates pass. This document describes verifiable behavior, not consciousness or universal superiority as an unproven fact.

## Capabilities Under Validation

- Cross-platform feature and file-handler validation
- API, endpoint, route, port, link, workflow, and Markdown inventory
- QVillage model-card and realtime memory synchronization
- QVS seed verification, mask/QVS state handling, and parallel task coordination
- Trading, account, wallet, Cashon, and financial-manager safety contracts
- GitHub-hosted automation, local keepalive, checkpoints, telemetry, and recovery

## Model Comparison

QMOI compares itself only through reproducible benchmark suites with fixed datasets, prompts, versions, hardware, latency limits, safety cases, and task-specific metrics. The result is written to `ollamatracks/model_evaluation.json`. A higher score is valid only for the measured task and environment; no model is declared best across all tasks without independently reproducible evidence.

## Health Gates

A model/runtime state is healthy only when model availability, inference, tests, links, workflows, memory synchronization, security checks, and checkpoint/success-contract evidence pass. Failures produce `review_required` or a bounded fallback, never a false success.

## Updates

`MODEL_CARD.md` and `QMOI_MODEL_CARD.md` are regenerated during every autonomous refresh. QVillage-linked documentation and model evidence are counted. `QMOIMODELTESTS.md` defines the required test surface.
