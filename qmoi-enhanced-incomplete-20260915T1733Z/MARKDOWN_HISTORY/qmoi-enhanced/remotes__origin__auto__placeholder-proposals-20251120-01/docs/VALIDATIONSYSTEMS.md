# QMOI Validation Systems

This document describes the validation systems implemented by QMOI/LION. It links to the specific validations for artifacts, apps, links, and documentation.

Validation systems:

- Download validation — validates build artifacts, checksums, timestamps and signatures.
  - See: `docs/DOWNLOADVALIDATION.md`
- App validation — builds, installs and smoke-tests apps per platform.
  - See: `docs/APPSVALIDATION.md`
- Link & docs validation — validates all links and anchors in `.md` files and produces `docs/link_report.json`.
  - See: `scripts/validate_and_fix_md.py` and `docs/LINKVALIDATION.md` (generated by orchestrator)
- Placeholder validation — scans for placeholder tokens across the repo and produces `docs/placeholders_report.json`.
  - See: `scripts/scan_replace_placeholders.py`

Operational model
-----------------

The orchestrator script `scripts/run_validations.py` coordinates these subsystems. It:

- Loads the canonical build report (`qcity-artifacts/qmoi_build_report.json`).
- Verifies artifact presence and checksums (download validation).
- Runs the markdown link validator in dry-run or apply mode (link validation).
- Runs the placeholder scanner (dry-run by default).
- Writes per-subsystem JSON reports into `docs/`.

Governance and safety
---------------------

- All automated fixes require an explicit `--apply` flag.
- Backups are created with `.bak` before any file-write.
- Large binary artifacts should be produced by CI and published to a release bucket or GitHub Releases; the repo should not store production binaries.

Next steps
----------

Principles

- Real-time validation status surfaced in docs via LION tags and `docs/*.json` reports

1. Reads `qcity-artifacts/qmoi_build_report.json` and verifies artifacts exist and checksums match.
2. Runs link validation and documentation checks (`scripts/validate_and_fix_md.py`).
3. Produces machine-readable reports in `docs/` (e.g. `docs/download_validation_report.json`, `docs/link_report.json`).
4. Optionally opens PRs or blocks deployment on critical failures.

# QMOI Validation Systems

This document describes the validation systems used by QMOI and by the LION runtime to ensure the repository, releases, and runtime artifacts are correct, installable, and safe.

Top-level validation systems

- APPS VALIDATION (`docs/APPSVALIDATION.md`): validates app builds for every supported platform, verifies packaging, signatures, checksums and basic installability checks (simulation on supported platforms and/or smoke tests in containers/emulators).
- LINK VALIDATION (`docs/LINKVALIDATION.md`): validates all links in the documentation and code (HTTP(S) links, local relative links, and anchors). Can auto-upgrade http→https when safe.
- DOWNLOAD VALIDATION (`docs/DOWNLOADVALIDATION.md`): validates download locations and artifact integrity (presence, checksum, size, signature verification, timestamp/retention policy).
- MEMORY VALIDATION (`docs/MEMORYVALIDATION.md`): validates how QMOI uses memory for its datastore and short/long-term memory, ensuring consistency, data lifecycle policies, and testable recovery.
- LION VALIDATION (`docs/LIONVALIDATION.md`): how the LION runtime validates agent configuration, permissions, orchestrator access, and self-heal procedures.

How these systems interact

- A single orchestrator (`scripts/run_validations.py`) ties all validation systems together and runs them in a configurable pipeline. The orchestrator generates machine-readable reports under `docs/` and creates prioritized remediation items in `docs/merged_remediation_plan.md`.
- LION integrates with the orchestrator via `tools/lionlaunch.json` and `tools/lionctl` to bootstrap, run, and self-heal validation runs.

Where to find implementation

- Orchestrator script: `scripts/run_validations.py`
- Link and markdown validation: `scripts/validate_and_fix_md.py`
- Placeholder scanning: `scripts/scan_replace_placeholders.py`
- Build/artifact verification: `qcity-artifacts/qmoi_build_report.json` and `downloads/`

Guiding principles

- Safe-first: automated fixes require explicit `--apply` flags and create `.bak` files.
- Auditability: all runs produce timestamped JSON reports under `docs/`.
- Reproducibility: use CI runners for artifact builds; do not commit large binaries to the repository—use Releases or an artifacts bucket.
- Incremental remediation: prefer PRs per area (docs, UI components, builds) for human review.
